# Coreweaver Labs Flagship Build Brief

## Decision

Coreweaver will become a focused **growth-infrastructure operator**. The flagship will help organizations make their identity, proof, distribution, and measurement systems more coherent across human and AI-mediated discovery. It will replace the current sprawling “agent governance / decentralized infrastructure / compliance product” narrative with a disciplined operating-system narrative.

The public build will not present unverifiable product performance, compliance outcomes, consensus measurements, production deployments, blockchain anchoring, invented personnel, customer proof, or legal conclusions. The existing VaaS and mandate routes will be reduced to clearly bounded working notes rather than sold as operational products until a controlled source packet supports stronger claims.

## Information architecture

## Visual system

The build uses **signal-field editorialism** rather than a generic SaaS dashboard or a decorative cyberpunk scene. The palette combines near-black ink, warm bone, electric blue, acid lime, and restrained orange for human-visible system state. The primary page device is a precise coordinate field and a four-node signal path. High-contrast editorial typography carries the argument; a mono layer carries labels, states, and methods.

Motion remains restrained and respects reduced-motion preferences. The implementation favors semantic HTML, visible focus states, keyboard-safe navigation, and lightweight CSS rather than a framework-heavy animation layer.

## Acceptance tests

| Gate | Pass condition |
| --- | --- |
| Claim discipline | No public file contains performance metrics, named internal swarms, BFT, cryptographic anchoring, legal/compliance guarantees, or unverified partner/employee relationships. |
| Route integrity | Home, Blog, Mandate, and VaaS return valid rendered pages; redirects continue to resolve intentionally. |
| Content integrity | Every visible claim is either a method, a scope statement, a proposal, or directly inspectable public evidence. |
| Accessibility | One `h1` per page; correct heading order; visible focus styles; descriptive controls; color is not the sole state signal; reduced motion is respected. |
| Responsive behavior | Key interactions and reading flow remain usable at 390px, 768px, and desktop. |
| Technical release | `npm run build` passes; generated HTML has consistent canonical, social, and structured metadata; the existing Vercel contract remains unchanged. |

## Known dependencies

The GitHub repository is authoritative for the Astro/Vercel property and has a clean baseline at commit `c993451`. The current public domain reflects that codebase. A production release requires confirmation of the connected Vercel deployment target and the user’s explicit approval immediately before the consequential external publish action.
